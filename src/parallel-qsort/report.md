# 四线程快速排序观察报告

题目：四线程快速排序观察（cpp-optional-parallel-qsort）
语言与线程库：C11 + POSIX 线程（`pthread`）
实验数据：题面给出的 16 个整数，直接写进源码（`DATA[16]`），不依赖外部文件。

```
42 7 19 42 3 88 15 7 61 0 54 23 91 15 36 100
```

## 1. 线程

**创建位置**：全部工作线程都在 `sort_range()` 里创建。每完成一次划分，程序计算左右两个区间的长度，把**较大的一侧**交给新线程，**较小的一侧留在当前线程**继续处理：

```c
    if ((p - lo) >= (hi - p)) {          /* 左侧更长，交给新线程 */
        plo = lo;     phi = p - 1;
        slo = p + 1;  shi = hi;
    } else {                             /* 右侧更长，交给新线程 */
        plo = p + 1;  phi = hi;
        slo = lo;     shi = p - 1;
    }

    if ((phi - plo + 1) > CUTOFF && take_slot()) {
        Task *t = malloc(sizeof *t);
        t->a = a; t->lo = plo; t->hi = phi;
        if (pthread_create(&tid, NULL, worker_main, t) == 0) { ... }
    }
```

**如何保证不超过 4 个**：用一个全局计数 `slots_used` 记录已经创建的工作线程数，上限为 `MAX_WORKERS = 4`。创建之前必须先"抢名额"，抢不到就直接走串行分支：

```c
#define MAX_WORKERS 4

static pthread_mutex_t slot_lock = PTHREAD_MUTEX_INITIALIZER;
static int slots_used = 0;

static int take_slot(void) {
    int ok = 0;
    pthread_mutex_lock(&slot_lock);
    if (slots_used < MAX_WORKERS) {
        slots_used = slots_used + 1;
        ok = 1;
    }
    pthread_mutex_unlock(&slot_lock);
    return ok;
}
```

名额只减不增，所以整个进程生命周期内累计创建的工作线程最多 4 个。另外，程序**不会在每一层递归都无条件开两个线程**：只有"待并行的一侧长度大于 `CUTOFF`"且"名额还有剩余"时才创建，两侧中的另一侧始终由当前线程处理。这两条约束叠加，既使 16 个数的输入无法开出超额线程，也让更大的输入稳定停在上限。

**背景对照**：此前用 Go 写过短视频网站的后台，接触过 goroutine 与 `sync.WaitGroup`——任务用 goroutine 派发，主流程用 `WaitGroup` 等一批任务结束，线程数量和调度由运行时管理，代码里不需要手工数线程。本题用 C 的 pthread，创建工作线程是显式的 `pthread_create`，等待是显式的 `pthread_join`，"最多 4 个"也必须由程序自己用计数器把关。

## 2. 划分与汇合

**基准与划分方式**：采用 Lomuto 划分，取区间最右元素 `a[hi]` 作为基准。用 `i` 维护"已确认小于基准"的边界，`j` 从左往右扫描，遇到小于基准的元素就与 `a[i]` 交换并前移 `i`；扫描结束后把基准换到 `i` 的位置，返回 `i`：

```c
static int partition(int *a, int lo, int hi) {
    int pivot = a[hi];
    int i = lo;
    for (int j = lo; j < hi; j++) {
        if (a[j] < pivot) { swap_int(&a[i], &a[j]); i = i + 1; }
    }
    swap_int(&a[i], &a[hi]);
    return i;
}
```

划分后左区间是 `[lo, p-1]`（全部小于基准），右区间是 `[p+1, hi]`（全部不小于基准），基准本身已在最终位置，两个子区间互不重叠——因此不同线程操作的是数组的不同片段，不需要对数组加锁。

**串行截止条件**：区间长度 `<= CUTOFF = 4` 时停止拆分，改用插入排序。数据量很小时插入排序常数小，也省掉创建和汇合线程的开销。此外还有一重终止条件：名额用尽时，剩余区间一律串行处理。

**汇合位置**：在**创建线程的那一帧**里汇合。当前线程先把自己负责的一侧排完，再 `pthread_join` 等待子线程：

```c
        if (pthread_create(&tid, NULL, worker_main, t) == 0) {
            sort_range(a, slo, shi);   /* 当前线程处理另一侧 */
            pthread_join(tid, NULL);   /* 汇合：等子线程排完 */
            return;
        }
```

子线程内部如果再创建线程，也会在它返回之前 join 掉自己的子线程。于是主线程从 `sort_range(a, 0, n-1)` 返回时，所有后代工作线程都已结束，程序退出前不存在未汇合的线程。

## 3. 正确性

用四种可复核的方式确认结果有序：

1. **相邻元素检查**：排序后线性扫描一遍，统计满足 `a[i-1] > a[i]` 的位置数，结果必须为 0。
2. **与标准库对照**：把同一份输入复制一份交给 C 标准库的 `qsort` 排序，再用 `memcmp` 逐字节比较两个数组，必须完全一致。
3. **ThreadSanitizer**：用 `gcc -std=c11 -fsanitize=thread -pthread` 重新编译，在题面数据和 `n=4096` 两组输入上运行，stderr 无任何报告，即未检测到数据竞争。
4. **随机压力测试**：`n=500` 的随机整数、200 组不同随机种子，全部通过上述第 1、2 项检查。

题面数据（16 个整数）的实际运行结果：

```
排序结果:  0 3 7 7 15 15 19 23 36 42 42 54 61 88 91 100
相邻逆序对=0
与 qsort 结果一致=是
创建工作线程=2（上限 4）
退出码=0
```

同一程序在不同规模下实际创建的工作线程数（均为随机数据，观察上限是否被突破）：

| n | 创建工作线程 |
| --- | --- |
| 8 | 1 |
| 12 | 2 |
| 16 | 4 |
| 32 / 64 / 129 / 1000 / 4096 | 4 |

线程数取决于划分后各区间的长度和剩余名额，不是固定值；题面这 16 个数在本次运行中使用 2 个。所有规模下都未超过 4 个。

## 4. 环境限制

- **平台的实验环境是只有 1 个 CPU 的沙盒。** 四个工作线程共享同一个核心，只能分时轮转，没有真正的并行执行。因此本报告中的耗时只是观察记录，**不能解释为并行加速，也不构成性能得分**；在单核上并行版本完全可能比串行版本更慢，这是预期结果。
- **本地复核环境与沙盒不同**：本地在 WSL2 中编译运行，`nproc` 报告 32 个逻辑 CPU。为了尽量贴近沙盒条件，另外用 `taskset -c 0` 把进程限制在单个 CPU 上重跑，排序结果、创建线程数和退出码都与多核环境一致；该次观测耗时在 0.3 ms 量级，受进程启动、调度与计时精度影响很大，同样只作记录，不用于任何比较。
- 本题的观察目标是**线程如何创建、如何被上限约束、如何汇合，以及结果是否正确**，而不是性能数字。

## 附：源码

源码 `qsort_threads.c` 按题面要求留在本地，未随报告提交。关键片段见第 1、2 节；完整结构为：

- `take_slot()`：互斥锁保护的名额分配，上限 4
- `partition()`：Lomuto 划分，取最右元素为基准
- `insertion_sort()`：区间长度不超过 `CUTOFF` 时的串行排序
- `sort_range()`：划分、决定哪一侧开线程、串行递归、`pthread_join` 汇合
- `worker_main()`：线程入口，调用 `sort_range()` 后释放任务结构
- `main()`：准备数据、计时、排序、输出检查结果（相邻逆序对、与 `qsort` 是否一致、创建线程数、耗时）
